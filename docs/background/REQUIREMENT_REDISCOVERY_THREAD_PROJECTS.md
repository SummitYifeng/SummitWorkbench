## 0. 一句话摘要

> 用户真实的工作资产是**按公司业务主题持续追加的知识线程**（财务运营体系建设、Coach 财务梳理、
> 报名系统优化、与木子/冯老师/饶杰的推进往来…），而 SummitWorkbench 当前把「项目」绑定为
> **Work 目录下的 git 仓库文件夹**。错位导致：业务线程在系统里没有档案 → 会议提取的项目几乎全部
> `unresolved` → 大量行动/决策沦为全局 inbox 孤儿 → 「今日·项目推进」只剩 git 信号与飞书任务，
> 看不见真正的业务线。改造方向：**vault 内新增「知识线程项目」一等公民**（不依赖 Work 目录文件夹
> 与 git 仓库，内容即 demo 三件套：主档案 + 按次追加的推进日志 + AI 产物文档），与现有仓库项目
> 两条腿并存；审批落点、项目页、首页推进卡、第二大脑全部打通线程维度。

## 2. 现状产品模型 vs 真实需求（错位证据）

### 2.1 现状模型

- **项目 = Work 目录顶层文件夹**（`~/Documents/Work/`），`_vault/projects/<文件夹名>.md` 为主档案
  （固定区块：`## 当前状态 / ## 下一步 / ## 阻塞 / ## 决策记录`）。
- 首页/项目页数据源 = **文件夹扫描**（`project_scan.py`，跳过 `_vault`）+ 档案 `status` 过滤；
  「在工作台」= 已建档且 `status: active`。
- 推进信号：**git 未提交/落后** + 项目 inbox 积压 + 主档案「下一步」（`project_scan` 只读本地 git）。
- 审批落点（`domain/review.py` RouteTarget）：全局 inbox / 项目 inbox / 项目主笔记 / 飞书任务 /
  新建会议；目标项目 `unresolved` 时 AI **不得自造项目名**，一律路由全局 inbox（零摩擦兜底）。
- 第二大脑检索（`workflows/ask/retrieval.py`）：**只遍历 vault 内 Markdown**，按路径/frontmatter/
  全文召回；vault 本身是 git 仓库、有 GitHub remote（`yifeng93/YifengWorkKnowledge`），每日自动提交。

### 2.2 用户观察到的症状（均属实）

1. **审批「目标项目」几乎全 unresolved**：`_vault/review/meetings.md` 中 2026-08-31 财务对齐与
   2026-09-02 曹木子沟通对齐会议的候选全部 `target_project: unresolved` → 全部 `route: global-inbox`。
   根因：内容属于 Coach / Finance Ops / 报销审批等**未建档主题**，AI 老实标 unresolved。
2. **全局 inbox 沦为业务线程孤儿院**：`inbox.md` 躺着「由木子承担财务BP」「财务系统化梳理先做
   Webclass 和 Coach」等决策——它们本该进入对应线程的决策记录。
3. **今日·项目推进看不到业务线**：2026-09-03 晨间简报「需要行动 5/5」中 4 条是飞书任务、1 条是
   git 未提交（HIC_Logistics）；真正在推进的业务线程（财务/Coach）无卡片。
4. **`_transcripts-inbox` 被当作「新文件夹」邀请加入工作台**：`project_scan` 只排除 `_vault`，
   把内部落料夹误判为未建档项目（产品 bug）。
5. **桌面 demo 文件第二大脑看不见**：ask 只检索 vault；`~/Desktop/demo/` 三份核心样本不在 vault，
   知识没有真正"链起来"。

## 3. 四轮访谈结论（决策表）

| # | 议题 | 结论 |

| R1 | 项目构成 | 公司业务/经营线程 + 个人/组织管理主题为主；代码/文档生产多转 PM 只读 + PRD/跟进 |
| R1 | 录入来源 | 会议纪要（自动）+ 与同事沟通消息 + 随手记 + AI 长对话产物；自己记工作日志（录音→自转写→文本） |
| R1 | 回看用途 | 「推进到哪了」现状+下一步 / 决策依据 / 工作回顾 / 新对话背景包（四项全要） |

| R3 | 推进日志单位 | **按次追加自然段**：日期+内容+涉及谁+类型（进展/决策/行动/待办/阻塞） |
| R3 | AI 产物入库 | 粘文本→AI 归类入库 + **入库自动生成摘要索引**；未选本地文件导入、未选提示更新主档案 |
| R3 | 回看形态 | **线视图（全貌）+ 第二大脑自然语言深挖/跨线，两者都要** |

| R4 | 线程档案位点 | 首页推进卡 + 审批目标项目下拉 + 项目页统一管理 + 第二大脑按线程检索（全选） |
| R4 | 主档案维护 | **系统自动写回为主**（审批通过的决策/下一步/责任自动入档；日志自动追加），不被反复追问更新 |
| R4 | 推进卡信息 | 下一步/阻塞 + **最近推进时间+摘要**（未选未决计数与关键人等待态，避免卡片过载） |
| R5 | 开发/生产类 | **双份模型**：协作知识（PRD/规则 → 仓库 docs/ 推送、开发拉取）与个人跟踪知识（vault 保持"有这件事+进度"）分开存，各司其职 |
| R5 | 桌面文件 | **不导入**：demo 仅示意知识形态，不作种子数据；真实知识经系统通道重建 |
| R5 | 首批试点线程 | 财务运营体系建设 / Coach 业务与财务规则 / 报名系统产品线 / ERP 探索 |

## 4. 目标模型

### 4.1 两类项目并存

```
项目（统一在「项目」页 / 审批目标项目 / 第二大脑出现）
├── 仓库项目（repo project）——现状不变
│     Work 目录 git 仓库文件夹 + _vault/projects/<id>.md 主档案
│     信号：git 状态 / 项目 inbox / 主档案下一步
└── 知识线程项目（thread project）——新增
      vault 内建档，不依赖 Work 目录文件夹，不建独立 git 仓库
      内容 = demo 三件套（见 4.2）
      信号：最近推进（日志时间+摘要）/ 主档案下一步 / 跟进事项未闭环
```

**实现要点**：registry 事实源已是 `_vault/projects/*.md`（`project_registry.py`），只需让「项目页/
审批下拉/第二大脑/首页」的数据源从「文件夹扫描 ⊂ 档案」扩展到「档案全集（含无同名文件夹的线程
档案）」。仓库项目由文件夹扫描补 git 信号（**仓库须在扫描范围内才显示 git 信号；不在 Work 下时
线程跟踪不受影响，repo 降级为纯被引用对象**），线程项目由日志/档案补内容信号。

### 4.1b 双份模型（开发/生产类的知识分工，R5）

协作与个人跟踪分开存，各司其职：

| 内容 | 存放 | 读者 |
|---|---|---|
| PRD、产品规则、验收口径（要交开发执行） | 仓库 `docs/`，推送后开发拉取 | 开发/协作方 |
| 「有这个事 + 进度」的个人跟踪（决策、跟进、复盘） | vault 线程档案（关联仓库项目 id 即可） | 罗艺峰 / 第二大脑 |
| 可复用规则/复盘（如排版校对规范、docx 质量复盘） | vault 线程档案（归入相应业务线） | 罗艺峰 / 第二大脑 |

桌面 demo 文件仅作形态示意，**不作为种子导入**（R5）。

### 4.2 线程的内容形态（demo 产品化）

一个线程 `finance-ops` 在 vault 中：

1. **主档案** `_vault/projects/finance-ops.md`
   - 现有固定区块：`## 当前状态 / ## 下一步 / ## 阻塞 / ## 决策记录`
   - 新增可选区块：`## 跟进事项`（他人承诺的责任记录：谁 / 承诺 / 状态 / 期限）
   - 决策/责任条目带角色字段（Owner / 确认人 / 执行人），写回格式含 actor/approver
2. **推进日志**（按次追加）——两种互补实现：
   - 显式时间线文档（可选）：线程内 `timeline.md`，append-only，AI/人工把重要节点整理成文
     （demo `HIC_finance_ops_erp_timeline` 即此类）；属 AI 产物入库。
   - 隐式聚合：带 `projects: [finance-ops]` 的工作日志/会议笔记按 project 过滤自动聚合出时间线
     （复用 ask 的 project 过滤机制）。
3. **AI 产物文档**（阶段总结/背景包/PRD）：入库为 vault 笔记，`project: <id>`，frontmatter 带
   自动生成的摘要，供检索命中；主档案「当前状态」可由其反哺（自动写回为主）。

### 4.3 审批路由扩展（落点语义补齐）

| 内容 | 落点（现状） | 落点（目标，线程项目语境） |
|---|---|---|
| 拍板决策 | 项目主笔记·决策记录 | 同左；条目带 角色（确认人） |
| 我的明确下一步（无期限） | 项目主笔记·下一步 | 同左 |
| 我的行动（有期限/涉及他人） | 飞书任务 | 同左（维持） |
| 不成熟想法 | 项目 inbox | 线程无文件夹 → vault `inboxes/<id>.md`（或主档案 inbox 区块） |
| **他人的行动项** | （现无） | 线程主档案 `## 跟进事项`（责任记录，不进本人待办） |
| 目标不明 | 全局 inbox | 同左（兜底不变） |

「目标项目」下拉：unresolved + 全部档案（仓库项目 + 线程项目）；批准写回前按 alias 解析。

### 4.4 首页 / 项目推进

- 推进卡两类并存：仓库项目卡保留 git chips；线程项目卡显示 **主档案下一步 + 「X 天前更新 · 摘要」**
  （活跃信号来自最近日志/产物/写回时间）。
- 线程的「下一步/阻塞/未闭环跟进」进入今日简报「需要行动·任务清单之外」（与现有仓库项目下一步
  同机制，R6）。
- 归档/加入工作台语义复用 `status: active/archived`；线程不需要时下首页，随时可恢复；生命周期为
  **手动归档为主 + 系统提示长期无更新**（不自动动它，R6）。
- 「新文件夹」横幅只针对**仓库类候选**（见 §6 bug 修复），线程建档走「新建线程」入口。

## 5. 改造方案（分层，P 为建议优先级）

### P0 —— 解当下痛点（工作量小、收益直接）

1. **内部目录不进项目视野**：`project_scan._VAULT_DIRNAME` 扩展为忽略名单
   （`_vault`、`_transcripts-inbox`，或约定"下划线前缀目录 + 可配置忽略名单"）。
2. **线程项目建档**：`wb project new` / Web「项目」页支持**新建知识线程**（无文件夹），
   产出标准 project-main 档案；项目页、审批目标项目下拉、第二大脑以**档案全集**为准。
3. **审批路由补线程落点**：
   - 目标项目可选线程档案；
   - 写回：决策（带确认人）→ 决策记录；我的下一步 → 下一步；
   - **新增他人行动项 → `## 跟进事项` 区块**（候选带 actor 字段，actor≠本人 → 跟进事项）；
   - 线程 inbox 落 vault `inboxes/<id>.md`（新目录，格式同全局 inbox）；
   - `domain/review.py` / `workflows/review_apply.py` / prompt（提取出 actor/确认人）同步。
4. **project-main schema 扩展**：`## 跟进事项` 成为可选固定区块；`domain/vault.py` 的
   required_blocks 与模板、`wb vault check` 同步（区块允许为空）。

### P1 —— 录入与沉淀闭环

5. **工作日志追加链路**：Web 全局/线程内「追加推进日志」输入框（文本粘贴，含**沟通往来手动摘录**，
   R6）→ AI 结构化（日期/摘要/涉及人/类型/关联线程 1..n）→ 写 vault 日志笔记
   （`projects: [...]`）→ 自动入各线程时间线聚合；审计与费用记账同现有链路。
6. **AI 产物入库**：线程视图「保存产物」→ 粘贴文本 → AI 命名归类 + 生成摘要（frontmatter）→
   写 vault（`project: <id>`）；「背景包」类产物可一键转为主档案「当前状态」草案。
7. **检索**：ask 支持 `project:` 线程过滤（CLI `--project` 已有雏形，Web 端暴露）；frontmatter
   摘要进入召回索引。

### P2 —— 线视图与推进呈现

8. **线视图页**：打开线程 = 当前状态 / 下一步 / 阻塞 / 跟进事项 / 决策记录 / 时间线（隐式聚合 +
   显式文档）/ 关联会议与产物；「追加日志」「保存产物」入口在视图内。
9. **首页线程推进卡**：下一步/阻塞 + 「X 天前 · 摘要」；与仓库卡统一排序（最近活跃）。
10. **简报提醒 + 生命周期提示**：线程「下一步/阻塞/未闭环跟进」进今日简报「需要行动·任务清单之外」；
    长期无更新线程在项目页/推进区给提示（手动归档为主，不自动动，R6）。

### P3 —— 强化（可选）

11. 内容停滞检测进周复盘/晨间简报「防止停摆」候选（线程 N 天无更新但有未决/未闭环跟进）；
12. 本地文件导入线程档案（用户未选，暂缓；桌面 demo 文件明确不导入，仅形态示意）。

## 7. 风险与待定

- **线程数量膨胀**：与仓库项目混排后首页可能拥挤——靠「在工作台/已归档」分层 + 卡片只显示
  活跃信号收敛（P2 验证）。
- **检索质量**：无向量库（硬边界 L29），thread 文档靠 frontmatter/全文召回；摘要索引字段用于
  提高命中，需真机抽查。
- **prompt 提取升级**：要求会议提取产出「涉及人/确认人」会略增 token 与漏判率；只对 action-item
  与 decision 要求 actor，缺失时仍按现状兜底（unresolved→全局 inbox）。

  「全库校验全绿」门禁。
- **与 PRD 的关系**：本文为非权威背景；批准后以 PRD 增补（如「知识线程项目」定义、L22 路由扩展）
  与 ADR 形式固化。
