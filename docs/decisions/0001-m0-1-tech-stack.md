# ADR 0001 · M0-1 工程与质量技术栈

- 状态：已接受
- 日期：2026-08-30
- 里程碑：M0-1（工程与质量骨架）
- 依据：`docs/product/PRD.md` v1.1、`docs/archive/plans/DEVELOPMENT_PLAN.md` §2.1 / §12

## 背景

M0-1 的目标是得到一个「可安装、可测试、可安全扩展」的 Python 工程底座，
不实现任何飞书 / 模型 / 会议 / 简报业务。开发计划要求首个 ADR 记录运行时、
CLI 框架、HTTP 客户端、schema 库与测试框架的选型。

## 决策

| 领域 | 选型 | 理由 |
|---|---|---|
| 运行时 | **Python 3.12+**（本机经 `uv` 使用 3.12.13） | PRD 锁定 3.12+；系统自带 3.9.6 不达标，改由 `uv` 托管解释器 |
| 打包 / 环境 | **uv + hatchling（PEP 621 `pyproject.toml`）** | 本机已装 uv 0.12.3；锁定复现快，`uv.lock` 提供确定性安装 |
| CLI | **Typer** | 类型注解直接生成命令与帮助；支持非交互运行与稳定退出码 |
| 数据校验 / schema | **Pydantic v2 + pydantic-settings** | 后续会议 / 模型结构化输出需严格 schema 校验；配置分层可复用同一体系 |
| HTTP 客户端 | **httpx** | 同步/异步一致 API，`MockTransport` 便于契约测试免真实调用；M0-1 仅纳入锁定，暂不写联网代码 |
| 测试 | **pytest** | 四层测试（单元 / 契约 / 集成 / 验收）通用；`CliRunner` 覆盖 CLI |
| 静态检查 / 格式化 | **ruff + mypy（strict）** | ruff 合并 lint 与格式化；mypy strict 守住领域类型边界 |

## 本批次交付

- `pyproject.toml`：包元数据、运行时依赖、`dev` 附加依赖、ruff / mypy / pytest 配置。
- `uv.lock`：确定性依赖锁定。
- `wb` CLI：`version` 与 `diagnose`（只读环境体检，退出码反映就绪度，绝不打印秘密值）。
- 配置分层：内置默认 < 本机 TOML < 环境变量 < 显式覆盖；路径基于 `$HOME` / `WORK_ROOT`，无用户名硬编码。
- 凭据引用：只存 Keychain 的 service/account，运行时按需解析为 `SecretStr`，不落盘、不入日志。
- 单元测试覆盖路径解析、配置分层、密钥保护与 CLI 冒烟。

## 明确不做（留待后续里程碑）

- 不加飞书 / 模型 / 会议 / 简报任何依赖与业务代码（严格串行门禁，见 PRD L44）。
- 不引入数据库、向量库、服务端或常驻进程。
- 不申请任何外部权限；不写任何真实凭据或真实会议内容进仓库。

## 后果

- 依赖面故意保持最小，业务依赖在对应里程碑开工时再增补并重新锁定。
- 换 HTTP 库或模型供应商时，领域层不受影响（端口适配边界见开发计划 §2.2）。
