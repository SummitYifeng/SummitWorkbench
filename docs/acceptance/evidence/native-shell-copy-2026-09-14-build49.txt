方法（隔离 HOME 让**已安装产物**进首启模式；主 App 不受影响）：

    TMPHOME=/tmp/wb-onb3; mkdir -p "$TMPHOME/Documents/Work"
    APP=/Applications/SummitWorkbench.app
    env HOME="$TMPHOME" WB_PANEL_MODE=production \
      "$APP/Contents/Resources/server/SummitWorkbenchServer" \
      --host 127.0.0.1 --port 8799 --work-root "$TMPHOME/Documents/Work" \
      --static-dir "$APP/Contents/Resources/web/static"
    # 然后 GET http://127.0.0.1:8799/  （受限 app 的 `/` 就是首启向导）
    # ⚠️ 必须给 --static-dir，否则服务拒绝启动：

### 5.1 「无法从二进制反查中文串」的根因（已查清）
不是修复没生效，而是**这些文案是短中文字面量（≤15 UTF-8 字节）**，Swift 的
small-string 优化会把它们**内联进代码、不放数据段** ⇒ `strings` 与原始字节搜索都查不到。

校准证据（同一份二进制，build 49）：

    代码里确实存在、且长度 ≤15 字节：关闭 ×0、确定 ×0、取消 ×0、好 ×0、端口被占用 ×0、已就绪 ×0
    代码里确实存在、且长度 ≥16 字节：复制诊断信息 ×4、正在探测服务 ×1、反复启动失败 ×2

第一次做这条验证时被这个现象误导过（以为「端口被占用」没进包），记在这里避免下次重走。

### 5.2 换成的做法：把文案抽成纯函数 + 功能单测（build 50）
- 新增 `native/SummitWorkbench/UICopy.swift`：`updateAvailable(version:)` 与
  `supervisorState(_:)`（11 个映射，含 `nil`）；
- 新增 `native/tests/UICopyTests.swift` + `scripts/test-native-automation.sh` 第二个运行段；
- 顺带修边界：版本号为空/全空白 → 「发现可用更新」（不留空冒号）。

实测（build 50 装机后复跑）：

    $ bash scripts/test-native-automation.sh
    native automation service manager tests passed
    native UI copy tests passed                              # 退出码 0

变异验证（把修好的地方改回去，必须红）：

    updateAvailable 退回 "发现可用更新 (version)"  → 退出码 133，报「更新提示必须带上实际版本号」
    .crashLoop 退回 rawValue                       → 退出码 133，报「状态 crashLoop 的中文名泄漏了 rawValue」
    .conflict  退回 rawValue                       → 退出码 133，报「状态 conflict 的中文名应为「端口被占用」，实际「conflict」」
    还原后                                          → 退出码 0
