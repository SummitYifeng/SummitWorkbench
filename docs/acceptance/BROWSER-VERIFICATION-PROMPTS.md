# 真实浏览器验证提示词（交给 Codex / Computer Use 执行）

> **给执行者**：本文件里的每个「提示词」都是自包含的，可以整段复制给具备 computer use 能力的 agent。
> agent 不需要读本仓库的其它文档，也不需要理解产品背景。

## 1. 为什么需要这份文档

本仓库的前端验证目前**止步于源码级契约**：`web/scripts/test-browser-contract.mjs` 检查的是源码里的
字符串与结构，**不会用真实浏览器执行构建产物**。因此下面这类问题源码测试永远抓不到：

- 打包器换了（例如 Vite 6 的 esbuild/Rollup → Vite 8 的 Rolldown）后产物行为改变
- 构建产物的资源路径、MIME、加载顺序问题
- 运行时异常（bundle 能构建但执行时抛错）
- 交互状态机（草稿、焦点、弹层）在真实 DOM 上的行为
- 响应式、主题、缩放、`prefers-reduced-motion`

**判定原则：只有真实浏览器里实际观察到的结果才算通过。** 源码断言、构建成功、`verify-build` 通过，
都不能替代本节列出的检查。

## 3. 通用约定（每个提示词都适用）

- **环境隔离**：使用临时 `HOME`、临时 `WORK_ROOT` 与临时 vault；**不要**使用真实工作区。
- **不碰外部系统**：不连接真实飞书、不调用真实模型、不推送真实远端 Git。
  本机若已配置真实凭据，必须在隔离 `HOME` 下运行以免误用。
- **只在本地读写**，不修改 `/Applications` 下的 App。
- **证据要求**：每条断言都要有截图或控制台/网络输出；**没有观察到就报告为"未验证"，不要推测**。
- **失败也算结果**：发现失败就如实报告，附最小复现步骤。

## 4. 提示词 A · 构建产物启动冒烟

> **适用时机**：任何前端依赖升级（Vite / TypeScript / esbuild）之后，合并之前。

```
你在一个 macOS 仓库里做一次「构建产物启动冒烟」。严格按下面执行，不要跳步，不要推测。

仓库：/Users/yifengstudio/Documents/GitHub/SummitWorkbench
产物目录：src/summit_workbench/webapp/static

背景（重要，避免踩坑）：生产环境里 index.html 位于 `/`，静态资源位于 `/static/...`。
构建产物使用 base='/static/'，所以 index.html 里引用的是 `/static/assets/index-*.js`。
如果你直接以产物目录为根启动静态服务器，JS 会 404，页面看起来"没渲染"——那是你的服务方式错了，
不是产物坏了。必须按下面的目录布局来服务。

步骤：
1. 准备一个临时目录 PROBE，让它的布局等于生产：
   - PROBE/index.html          ← 复制 src/summit_workbench/webapp/static/index.html
   - PROBE/static/             ← 复制整个 src/summit_workbench/webapp/static
2. 在 PROBE 上启动静态服务器（任意端口，只监听 127.0.0.1）。
3. 用真实浏览器（Chrome 即可）打开 http://127.0.0.1:<端口>/ ，等页面稳定后：
   a. 打开开发者工具，切到 Console，记录**所有** console 输出；
   b. 切到 Network，记录所有非 2xx/3xx 的请求。
4. 在页面上观察并记录：
   - 是否出现顶部品牌区「SummitWorkbench 外置执行管理层 · 第二大脑」
   - 是否出现六个页签，文字为：今日、审批、第二大脑、项目、指南、设置
   - 主内容区是否渲染出内容（本步骤只服务静态产物、没有后端，因此预期会看到
     「今日数据读取失败」一类错误提示，那是**预期行为**，不是失败）
5. 截图：整页截图 + Console 面板截图。

通过标准（全部满足）：
- HTML、CSS、JS 三类资源全部返回 200；
- Console 中**没有任何未捕获异常**（Uncaught / TypeError / ReferenceError / SyntaxError）；
  与后端 404 相关的网络错误提示**不算**未捕获异常；
- 六个页签全部渲染出来。

必须报告：
- 实际端口与完整 URL；
- 六页签是否齐全（逐字）；
- Console 的完整输出（尤其是任何红色报错）；
- Network 中每个非 2xx 请求的 URL 与状态码；
- 结论：通过 / 失败 / 未验证（附原因）。
```

## 5. 提示词 B · 六页签与页签内视图

> **适用时机**：打包器或前端框架/构建链升级后。

```
继续上一个任务的环境（或重新按同样的方式启动一个**带真实后端**的实例：在临时 HOME 与临时
WORK_ROOT 下运行 `wb web`，按向导新建工作区，模型与飞书两步选择「跳过」）。

逐项执行并截图：
1. 依次点击六个页签：今日、审批、第二大脑、项目、指南、设置。
   每点一个，确认：该页签变为选中态；主内容区渲染出对应该页签的内容；Console 无新异常。
2. 键盘巡航：焦点放在页签栏上，按 End 应到「设置」，按 ArrowRight 应回到「今日」，
   按 Home 应到「今日」；记录每一步实际落点。
3. 每个页签至少与页面的一个可见控件交互一次（例如设置页展开/收起「高级维护」，
   指南页搜索一个不存在的词并清除），确认无异常、无整页横向滚动条。

通过标准：六页签全部可切换且渲染；键盘落点与上述一致；Console 无未捕获异常；
页面 `document.body.scrollWidth <= window.innerWidth`。

必须报告：每步截图；键盘实际落点序列；任何偏差。
```

## 6. 提示词 C · 弹层焦点与草稿保护

> **适用时机**：升级后必须复验，这是最容易因构建差异而回退的交互。

```
在带真实后端的实例上（临时 HOME / 临时 WORK_ROOT，模型与飞书跳过）：

1. 打开任意一个弹层（例如顶栏「↩ 撤销」，或项目详情里的「✎ 日志」）。
2. 观察并记录：
   - 弹层出现后，键盘焦点是否**自动进入弹层内部**（记录焦点所在元素）；
   - 连续按 Tab，焦点是否**始终留在弹层内**，并在最后一个控件后回到第一个；
   - 按 Escape，弹层是否关闭；
   - 关闭后焦点是否**回到触发它的那个按钮**（截图证明）。
3. 草稿保护：在一个会保存草稿的弹层里（例如「✎ 日志」）输入一些文字，然后按 Escape。
   预期：出现「是否放弃草稿」一类的确认；选择取消时应**留在弹层且文字保留**。
4. 再次操作直到正常关闭，确认焦点归还。

通过标准：上述每一项都真实观察到；重点项是**焦点归还**与**草稿不被静默丢弃**。

必须报告：每一步的截图；焦点所在元素的标识；任何一项未通过时的最小复现步骤。
```

## 7. 提示词 D · 审批闭环（零写入预演）

```
在带真实后端的隔离实例上，并且**不连接真实飞书**。

1. 进入「审批」页。
2. 使用状态筛选、勾选若干待确认项，观察「当前选择范围」摘要是否正确。
3. 点击「检查并写回」，观察预演结果：

通过标准：预演标签出现且文案为零写入；筛选切换后选择被清空；无 Console 异常。

必须报告：截图；预演文案原文；确认本轮未执行任何写回。
```

## 8. 提示词 E · 导入抽屉

```
在带真实后端的隔离实例上（模型**未配置**也可以，这正是要验证的失败路径）。

1. 点击「导入会议」打开抽屉。
2. 选择一个或多个本地 `.md` / `.txt` 文件（可自建合成文件，内容随意但非空）。
3. 观察回执区域：每个文件都应有独立回执，显示文件名、大小、状态与原因。
   模型未配置时，预期回执为明确的失败原因，而不是静默无反应。
4. 关闭抽屉，再重新打开，确认**之前的回执仍在**。
5. 切换页签后再回来，确认回执仍保留。
6. 关闭抽屉后，确认焦点回到触发它的「导入」按钮。

通过标准：多文件回执持续可见；关闭重开不丢；无 Console 异常；焦点归还。

必须报告：截图（含回执列表与焦点）；每个文件的回执原文。
```

## 9. 提示词 F · 响应式、缩放与主题矩阵

```
在带真实后端的隔离实例上，逐档设置视口并截图：

视口：320×700、390×700、768×640、960×640、1280×820
对每一档记录：document.body.scrollWidth 与 window.innerWidth，并确认**无整页横向滚动**。

注意：页签栏内部出现横向滚动是**预期设计**，不算整页溢出。

然后：
1. Chrome 原生 200% 缩放（不是视口模拟），复查 1280 宽下是否仍可用、有无截断或重叠。
2. 切换到**浅色主题**，复查文字对比度与状态徽标可读性，截图。
3. 在系统设置中开启「减少动态效果」（或浏览器 `prefers-reduced-motion: reduce`），
   确认动画/过渡被抑制而非仍大量播放。

通过标准：五档均无整页横向溢出（给出实测数值）；200% 缩放可用；浅色主题可读；
reduced-motion 生效。

必须报告：每档的实测数值与截图；任何溢出、截断、对比度问题。
```

## 10. 提示词 G · 构建产物资源完整性与动态端口

```
1. 在提示词 A 的静态服务环境中，打开 Network 面板并强制刷新（禁用缓存）：
   - 列出全部请求，确认没有任何 404 / 500 / 被取消的请求；
   - 确认引用的 `assets/index-*.js`、`assets/index-*.css`、`index.html` 都是 200；
   - 确认 `build-meta.json` 中列出的每个 asset 都能 200 取到。
2. 记录当前页面 URL 的端口号。然后重启服务使其监听**另一个端口**，用新端口重新打开：
   - 确认应用仍能正常启动；
   - 确认不会因为端口变化而出现跨源或无法读取本地状态的问题（同源策略相关）；
   - 如实记录 localStorage / sessionStorage 中的草稿历史在端口变化后**是否丢失**。

通过标准：资源零 404；新端口下应用可正常启动；端口变化对本地状态的影响被如实记录
（丢失是已知行为，不算失败，但必须报告）。

必须报告：完整网络请求清单；两个端口的 URL；本地状态在端口变化前后的可见差异。
```
