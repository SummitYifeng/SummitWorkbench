总控中心架构

晨间指挥台 —— 每日编排 + 一键带上下文启动。底层是 Obsidian 记录底座，中间是三层薄结构，两侧是输入源与执行器，三条数据流以 A / B / C 标注。

这是随架构演进而更新的示意图，不是 PRD；与 THINKING_DOC.md 中的决策一一对应。

环 A · 晨间简报

飞书日历/任务 → 大脑 → Obsidian 每日笔记

定时把当天的日历与任务经飞书 MCP 拉取、解析，写成一份 brief 落进当天笔记。飞书业务数据尽量留在本地。

环 B · 一键启动

指挥台/大脑 → (带 AGENTS.md) → Codex → 项目

点一下就把选定项目的档案作为上下文，把 Codex 拉起来读代码、拉分支、写需求。不再手动选文件夹、口述背景。

环 C · 飞书办公

大脑 → 发消息 → WorkBuddy → 交付文件

飞书侧的文档/周报/表格杂活，通过消息派给 WorkBuddy 或本地的 OpenWorkBuddy。松耦合：只能发消息，不能被直接编排。

开放决策 #1：编排层（大脑）的落地方式未定，留给 Claude Code 在 PRD 阶段给方案。

v1 呈现：先用 Obsidian 每日笔记当指挥台，初期不做独立 App / 网页面板。

紧耦合 vs 松耦合：Codex 可脚本、可深度编排；WorkBuddy 只能被"发消息"驱动。

数据边界（L6）：代码可上云，飞书业务数据尽量本地 / 最小外传。

记录底座是地基：一切都沉淀进全新独立 vault，让 AI 越来越懂我。

项目档案：每个纳入平台的项目根目录放一份 AGENTS.md，即"AI 可读的项目档案"。
