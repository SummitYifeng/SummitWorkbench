# SummitWorkbench Web 使用指南（纯 Web 版）

> 适用版本：v0.4.4 build 9 · 本指南**不需要命令行**，所有日常操作都在 App 内完成。
> 本指南也**内置在工作台顶部的「指南」页签**（内容与本文档同步，离线可看）。
>
> 工作台 = 你的本地执行管理层 + 第二大脑：记一笔 → 批一轮 → 喂一场会，一个页面闭环。
> 纯本地运行（127.0.0.1），数据只存在你的 Mac 上，不上传任何内容。

## 1. 打开工作台（不用敲命令）

- 从**「应用程序」文件夹或启动台**打开 **SummitWorkbench**（正式安装位为
  `/Applications/SummitWorkbench.app`，不在桌面）。安装包是自包含版本，不会自动读取开发仓库；
  更新版本时请用新的 DMG 覆盖安装，再退出并重新打开 App。
- 首次打开若被系统拦截（未签名应用）：右键点图标 → 「打开」→ 再点「打开」即可。
- 打开后弹出一个独立窗口显示工作台；**服务跟着 App 一起活着**，关掉窗口也不影响运行。
- 面板已开着时，桌面 App 会管理动态 loopback 端口，请优先继续使用 App 窗口；只有直接运行
  `wb web` 时才使用默认的 `http://127.0.0.1:8787`。

> 说明：工作台以「后台代理」方式运行，**不会出现在程序坞**（所以没有图标弹跳的烦恼）。
> 想再打开窗口：从「应用程序」打开 SummitWorkbench（服务已在跑时会直接弹出窗口）。桌面 App
> 使用动态 loopback 端口，请优先使用 App 窗口；只有直接运行 `wb web` 时才访问默认的
> `http://127.0.0.1:8787`。

> 退出工作台（停止本地服务）：点面板顶栏右上角的 **「退出」** 按钮（会先弹确认），
> 服务随即停止并关闭窗口。下次要用再从「应用程序」打开 App 即可。

> 撤销系统改动（恢复误写回）：点顶栏右上角 **「↩ 撤销」**——系统每次自动写回（捕捉/日志/产物/审批应用/项目建档归档等）都会自动 git 留痕，可在弹层里查看最近自动提交的差异并一键还原。**还原只作用于 vault 文件**；飞书侧已产生的副作用（已建任务/会议、已完成状态）不可撤销，界面文案也会明示。

顶部有六个页签：**「今日」（默认）| 「审批」| 「第二大脑」| 「项目」| 「指南」| 「设置」**。下面分页说明。

> v0.4.4 的使用顺序可以记成：先看置顶简报，再在简报快捷行捕捉，必要时从抽屉导入会议，最后到审批页确认写回。

> 生成简报后，系统会把本次生成的当日笔记、快照和相关运行信号作为一组显式路径自动提交并同步，
> 不会把 vault 中其他未提交的手工改动一起带上。若顶部状态暂时没有刷新，点一次右上角 ↻；
> 只有确实存在未提交手工改动时才需要处理 `dirty-protected`。

## 2. 「今日」页（默认首页）

打开第一眼，从上到下就是今天该做的事：

### ① 今日简报（置顶）

- 今日简报是首页主角，顶部显示日期、健康度和「↻ 重新生成」；没有简报时直接显示「⚡ 现在生成（约 30 秒）」。
- 宽屏下左侧是「今天日程」，右侧是「待办任务 + 需要行动」；窗口变窄后自动回到单列。
- 「AI 提议（非事实）」和「最近完成」默认折叠，事实与待办先展开。

### ② 简报快捷行：捕捉与会议导入

- 输入一行，按回车即记入全局 inbox，不跳转不刷新；捕捉已经并入简报快捷行，不需要在页面之间寻找入口。
- 系统会自动判断这是**承诺**（要去做的事）还是**想法**（灵光/备忘），并识别截止日期；右下角会弹出提示，如「已记入全局 inbox · 承诺（截止 2026-09-10）」。
- 想关联项目就写 `#项目名`（用已建档项目的名字或别名），例如：`周三前给老王样章 #排版`。
- 即使 AI 没配置/超时，内容也会按「想法」安全保存，**永远不会丢**。

同一行的「＋ 导入会议纪要」会打开右侧抽屉。会议导入收进抽屉是为了让首页保持聚焦：可以先继续浏览简报，抽屉关闭后不会丢失已选文件。

### ③ 待确认审批卡片

- 有积压时显示橙色卡片：「N 条待确认 · 最老已等待 X 天」+「去处理 →」按钮，一键跳到审批页。
- 处理干净后变绿色「审批已清空」。

### ④ 导入会议纪要（快捷行抽屉）

- 点击简报快捷行的「＋ 导入会议纪要」打开抽屉，再把飞书导出的逐字稿（`.md` / `.txt`，带说话人+时间戳）拖进去，或点「点击选择文件」。
- 导入后**全自动**：归档原文 → 结构化笔记 → 提取项进入审批页；结果区回显「处理 N / 跳过 N / 失败 N / 生成候选 N」和预估费用。
- 文件名建议 `YYYY-MM-DD-会议标题.txt`（日期和标题的来源）。
- 自动处理只到「生成候选进审批页」；**批准写回仍要你在审批页逐条确认**——系统不会未经你同意改动项目和飞书任务。

### ⑤ 项目推进卡（只显示你在工作台的项目）

- 这里的卡片**不是** `~/Documents/Work` 下所有文件夹的目录——只有**已建档且「在工作台」的
  项目**（仓库项目 + **知识线程项目**）会显示，避免项目一多首页被淹没。
  知识线程卡显示「知识线程」徽标、「最近活跃」日期与停滞提示（>14 天无实质更新），仓库项目卡显示 git 信号。
- 每张卡：git 未提交/领先落后（仓库项目）、项目 inbox 积压、主笔记里的「下一步」；
  有动静的卡片左侧高亮成警告色。
- **「新文件夹」横幅**：当工作目录里出现还没建档的项目文件夹时，项目区顶部会出现一条提示（不占卡片位），逐条可点 **「加入工作台」**（建档并出现在推进卡）或 **「归档」**（记录为已归档、不再提示）。处理完横幅即消失。
- 想调整哪些项目上首页：每个在工作台的项目卡片右下角都有 **「归档」** 按钮——点它、确认后
  项目即从首页消失（文件夹与笔记不动），想找回时去「项目」页点「加入工作台」即可恢复；
  批量管理走标题行右侧的 **「管理全部 →」**。
- 每张项目卡/行（已建档的）还有两个入口：
  - **✎ 日志**：把今天的推进（与谁沟通了什么、定了什么、下一步）粘进去，可同时勾选多个
    线程/项目——AI 会整理成摘要归入各线程时间线（模型不可用时只存原文，绝不丢）；
  - **存产物**：把和 AI 长对话产出的阶段总结 / 背景包 / PRD 全文存进所选线程档案，自动命名 +
    生成摘要索引，之后第二大脑随时能检索到。
- **点项目名打开「线视图」**：档案区块（当前状态 / 下一步 / 阻塞 / 跟进事项 / 决策记录）+
  时间线（该线程的推进日志、产物、关联会议按日期聚合）一屏看全；视图内可直接「✎ 日志 /
  存产物 / 刷新」。日志或产物入库会刷新项目卡的「最近活跃」（activity_at）；「>14 天未更新」  只按实质更新（建档/激活/归档/改名/状态确认）判断，机器活动不会把它刷掉。

### ⑥ 今日简报（日程优先视图）

- 每天 08:00 自动生成；没生成时显示「⚡ 现在生成（约 30 秒）」按钮，点一下立即生成。
- 简报是当天晨间指挥台，从上到下分四层：
  1. **会议**：左侧固定时间列，已过去的会议自动淡化。行尾有 **「✎」小圆钮**的，点开可改会议标题与起止时间——改动直接写回飞书日历（个人日程，不邀请他人），保存后行内即时更新。
  2. **待办任务**（主清单，按截止紧迫度排序）：每行左侧是**截止徽章**——今天到期（红）/ 剩 1–2 天（琥珀）/ 一周内（蓝）/ 更远只看日期（灰）；行尾带 **「近期承诺 · #N」** 彩色注解的，是 AI 挑出今天最该推进的**今日优先**项（序号即推荐顺序，注解直接标在对应任务行上，与清单合一、不重复列两遍）。**每行最右有两个小圆钮**：**「✓」** 在飞书中把该任务标记为已完成（写回任务本体，行随即消失并计入「最近完成」）；**「✎」** 改任务标题与截止日期（清空截止 = 移除截止），同样直接写回飞书任务。
  3. **需要行动 · 任务清单之外**（有才显示）：不在飞书任务清单里的行动——如「提交 XX 的未提交改动」（git 未提交）、项目下一步、inbox 积压等，附分类注解与来源。
  4. **AI 提议（非事实）** 与 **最近完成**：默认折叠成一行（带条数），点开查看。
- 降级日（采集源失败 / 排序回退）简报顶部会出现黄色健康度提示；有待确认提取时也有提示条可直达「审批」页。
- vault 里的 Markdown 原文不变（Obsidian 里读到的还是原来那份简报）。

> 宽屏布局不是另一套数据：只是把日程和任务并排展示；窗口较窄时自动单列，滚动顺序和内容保持一致。

## 3. 「审批」页

### 单条候选操作

- **✓ 批准**：写回目标（项目主笔记 / 飞书任务 / **新建会议** / inbox），点击即生效，无需整页刷新。
- **✗ 拒绝**：归档为忽略项。
- **↺ 改回待确认**：误操作可撤回。
- **修改**：展开表单可改正文、目标项目、落点（route）、截止日期；「目标项目」输入框有
  项目建议下拉（已建档的仓库项目与**知识线程**），填项目 ID 或别名均可；留空 = 走全局 inbox。
  落点选 **「新建会议」** 时会出现 **开始时间 / 结束时间** 两个输入框（结束留空则按开始 + 1 小时），
  保存后即时生效。批准此类候选并点「应用（写回）」就会在飞书日历里**新建一条日程事件**
  （以候选正文为标题、不邀请他人）。
- 落点含义速查：
  - **飞书任务**：有截止或涉及他人、要落执行清单的 → 在飞书建任务；
  - **新建会议**：会议结论 =「X 时再开会」→ 飞书日历建日程；
  - **项目主笔记**：你自己明确的下一步 → 写进项目档案「下一步」；
  - **跟进事项**：**别人**承诺要做的（木子/冯老师…）→ 写进项目档案「跟进事项」责任记录
    （`- [ ]` 待闭环，不进你的飞书任务，闭环后手动勾掉）；
  - **项目 inbox**：归得清项目、还不成熟的想法 → 仓库项目写文件夹 inbox；**知识线程写
    vault `inboxes/<项目>.md`**；
  - **全局 inbox**：归不清项目 → 全局收件箱兜底，绝不丢。
- 依据或目标项目缺失的候选会显示「⚠ 暂不可批准写回」——这是缺信息，不是故障。
- 截止日期早于今天的待确认候选会在元信息标注「已过期」。

### 批量操作

- 每个会议分组标题右侧有「✓ 全批 / ✗ 全拒」：一键把该组**待确认**条目全部批准 / 全部拒绝（已裁决的条目不受影响）。
- 工具栏「一键拒绝过期项」：把截止早于今天的全部待确认条目批量置为拒绝（如清理测试会议的过期数据）。
- 工具栏「预演应用」：弹窗展示零写入的 DRY-RUN 计划（每条候选要去哪）；「应用（写回）」对全部已批准条目执行写回。

### 清理测试/旧会议（CLI）

- `wb review sweep`：预演列出将退役的会议笔记与候选数（零写入）。
- `wb review sweep --apply`：执行——该会议候选批量拒绝、笔记状态置 ignored（正文原文保留）、任务状态收口；之后 `wb review refresh` 不会再捞回它们。
- `wb review sweep --before 2026-08-28 --apply`：只清理会议日期早于 2026-08-28 的旧会议。
- 新导入会议请用收紧后的提取（prompt v3）：只有拍板的决策和「谁、何时前、做什么」明确的行动项才进审批页。

## 4. 「第二大脑」页

- 问答式追问：先问一句（如「网课项目最近的决策是什么？」），回答分「事实（带来源）」与
  「建议（模型推断）」两区，来源以 `[[笔记]]` 链接给出。
- 提问框上方有 **检索范围** 下拉：默认「全部（整个第二大脑）」；选某个线程/项目后，只在这条
  线的档案、推进日志、产物与关联会议里找答案（如选「FinanceOps」问「木子最近推进到哪了」）。
- 可以**在同一会话里继续追问**（「那后来呢？」），上下文自动带上之前引用过的来源；会话保存在
  本地浏览器（最多 10 个），可新建/切换/重命名/删除。
- 模型不可用时显示可见错误说明，不会白屏。

## 5. 「项目」页（全部项目管理）

- 列出**两类项目**：仓库项目（`~/Documents/Work` 下的文件夹）与**知识线程项目**（业务线程，
  纯 vault 档案，不需要文件夹/git 仓库），每行带状态徽标：**在工作台**（绿）／**新**（黄，
  还没建档，仅仓库文件夹）／**已归档**（灰）。
- 顶部搜索框按项目名过滤；排序为 在工作台 → 新 → 已归档。
- **＋ 新建知识线程**：业务线程（如「财务运营体系建设」「Coach 财务梳理」）不需要在
  `~/Documents/Work` 建文件夹，直接在 vault 建档即可被会议审批解析命中、出现在推进卡与
  第二大脑检索里；想调整「项目 ID + 别名」随时可改档案。
- 行内操作：
  - **加入工作台**：未建档的「新」文件夹会建档并上首页；已归档的项目点它即**恢复**；
    知识线程同样可归档/恢复。
  - **归档**：把在工作台的项目归档（下首页）。归档/恢复只改 `_vault` 里的项目档案状态，
    **文件夹和 git 历史一概不动**。
- 系统内部目录（`_vault`、`_transcripts-inbox` 等以下划线开头的落料夹）**不会**出现在项目
  列表，也不会提示「加入工作台」。

## 6. 设置（四张白话卡）

设置页用四张白话卡说明连接状态，成功状态统一显示绿色「✓」：

- **工作区**：显示当前工作区文件夹。工作区就是保存会议、任务和项目资料的本地文件夹。
- **AI 模型**：粘贴 DeepSeek API Key，点击「连接并验证」。成功后显示绿色「✓ 已配置」；自定义模型收在卡内折叠区。
- **飞书**：点击「授权飞书」或「重新授权飞书」。浏览器完成授权后若回到 `localhost` 回调页，
  返回 SummitWorkbench 窗口继续操作即可；成功后显示绿色「✓ 已授权」，令牌失效时显示「需重新授权」。
- **自动化**：开关晨间简报、每周复盘、会议同步和每天检查更新，并可调整运行时间。

多工作台、Git 同步、健康检查、只读预检、诊断和版本更新等维护入口都在底部「高级与维护」折叠区，默认不展开。只有需要排查或切换工作区时才打开；展开不会改变数据。

## 7. 状态与提醒

- 顶栏健康点：绿色=正常，橙色=有积压/接近预算，红色=有异常（失败任务或飞书授权失效）。
- 页面每 60 秒自动刷新一次；也可点右上角 ↻ 手动刷新。
- 系统会在**待确认积压 / 费用超预算 / 定时任务失败**时自动发 macOS 通知提醒你（无需任何操作）。

## 8. 文件放在哪里

所有内容都在本地 Vault 中，按用途归类：

- **快速捕捉** → `_vault/inbox.md`，全局收件箱，保留待处理条目和分类标记。
- **项目资料** → `_vault/projects/<项目>.md`，一个项目一篇主笔记；项目的当前状态、下一步、阻塞和决策记录都在这里。
- **推进日志** → `_vault/logs/`，每次工作的过程记录；适合记录「做了什么、决定了什么、下一步是什么」。
- **会议证据** → `_vault/meetings/transcripts/` 保存完整逐字稿，`_vault/meetings/notes/` 保存结构化会议笔记。
- **审批与审计** → `_vault/review/meetings.md` 是待确认入口，`_vault/review/archive/` 保存已批准或已忽略记录。
- **产物与参考资料** → `_vault/artifacts/` 保存阶段总结、PRD、背景包等可复用成果，`_vault/insights/` 保存明确要留下的问答洞察。
- **每日与每周复盘** → `_vault/daily/` 保存每日简报，`_vault/reviews/weekly/` 保存跨项目复盘。
- **系统索引与运行信号** → `_vault/_views/`、`_vault/_signals/` 等下划线目录由系统维护，不手动编辑，也不当作项目资料。

全部是 Markdown + 本地文件（位于 `~/Documents/Work/_vault/`），随时可以用 Obsidian 打开查看、继续编辑。

## 9. 常见问题

**Q：双击图标没反应 / 页面打不开？**
A：工作台是后台代理、**没有 Dock 图标**，先从「应用程序」重新打开 SummitWorkbench。桌面 App
使用动态 loopback 端口，不要手工固定端口；仍不行可看日志 `~/Library/Logs/summitworkbench-panel.log`。

**Q：页面是旧的样子（白底表格、没有卡片）？**
A：依次检查：
1. 退出面板（网页顶栏「退出」）后**重新从「应用程序」打开 SummitWorkbench**——版本更新只在
   服务重启后生效；
2. 若仍旧，在面板页面按 **⌘⇧R 强制刷新**（浏览器可能缓存了旧页面，而旧页面引用的文件已
   被新版本替换）；
3. 确认你打开的是 **/Applications/SummitWorkbench.app**（当前安装的自包含 DMG 版本），不是
   /Applications 里的 SummitKnowledge / SummitServerAI——那两个是历史遗留旧产品，内嵌旧界面，
   与本仓库无关；若刚安装新 DMG，请退出后重新打开 SummitWorkbench；
4. 还不行则是前端产物没重建（找维护者执行一次 `cd web && npm run build` 并重启服务）。

**Q：明明工作目录里有很多项目文件夹，首页「项目推进」却很少/是空的？**
A：首页只显示**已建档且在工作台**的项目。未建档的文件夹会先出现在「新文件夹」横幅里，点「加入工作台」后才会成为推进卡；已归档的进不了首页。全部文件夹都能在「项目」页找到并管理。

**Q：快速捕捉一直显示「想法」？**
A：AI 分类需要模型配置（`[models.capture]` 或 `[models.shared]` + Keychain 里的 API key）。没配置时功能照常用，只是不分类、不识别截止日期。

**Q：拖入文件提示「未识别为逐字稿」？**
A：需要 `.md` / `.txt` 且内容非空；请确认导出的是逐字稿正文而非空模板。

**Q：导入或问答报「模型未配置」？**
A：这两项依赖云端模型。未配置时它们暂不可用，但捕捉、审批、简报生成等其余功能不受影响。配置好后重启 App 即可。

**Q：模型或飞书连不上怎么办？**
A：进入「设置」，看对应卡片顶部的连接状态；模型重新粘贴 Key 并点击「连接并验证」，飞书点击「重新授权飞书」。仍失败时，在「高级与维护」里运行在线健康检查，把白话错误提示和诊断包交给维护者。API Key 和授权令牌不会显示在页面或诊断包里。

**Q：修改审批候选后想撤销？**
A：用「↺ 改回待确认」或直接编辑回原值；审批页只改 `meetings.md`，不会触发任何写回。

**Q：任务在哪里点完成——工作台还是飞书？**
A：**两边都行，且双向同步**：在「今日」简报的待办任务行尾点小圆钮「✓」，会直接写回飞书把任务标记完成，该行随即消失、计入「最近完成」；在飞书里完成的任务，也会在下次简报生成（或刷新后重新生成简报）时反映——工作台把飞书当作任务状态的唯一真源。

**Q：为什么任务完成/编辑或新建会议偶尔提示失败？**
A：这些写回需要飞书授权有效且目标仍存在（如已删除的任务、被移动的日历事件会失败）。**新建会议与编辑会议还需要日历写权限**：先在飞书开放平台给应用开通「日历」读写 scope，然后在工作台重新授权一次（旧 token 不带新权限），之后即可用。

**Q：撤销系统改动（↩ 撤销）能还原什么？**
A：系统每次自动写回都会自动 git 留痕（消息以 wb: 开头）。顶栏「↩ 撤销」列出最近的自动提交，可先看差异再一键还原——只把 vault 文件恢复到该次写回前的状态。**飞书侧的副作用（已建任务/会议、已完成状态）不可撤销、不受还原影响**；若目标文件你有未提交的手动修改，系统会拒绝还原以免覆盖你的改动。

**Q：编辑会议/任务会改到 vault 里的简报吗？**
A：不会。改动只写回飞书本体，并镜像到当日的 Web 渲染快照（该行更新/消失）；vault 里的简报 Markdown 是当天早上的原始记录，一字不动，Obsidian 阅读不受影响。

## 10. 一句话总结

**每天：捕捉框记一笔 → 看审批卡片批一轮 → 把新会议的逐字稿拖进去 → 简报/问答兜底；
首页只盯你在工作台的项目，其余在「项目」页随时可取回。**
