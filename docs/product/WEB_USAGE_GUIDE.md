# SummitWorkbench 使用指南

> 这份指南讲**「想做什么事，就点哪里」**。照着做就行，不需要懂技术，也不需要打开终端。
> 全文也内置在 App 顶部的「指南」页签里，**断网也能看**。
>
> 想看当前装的是哪个版本：看**窗口顶栏右上角的状态文字**，它会实时显示
> （形如「界面 v… · 服务 x.y.z · 已同步」）——那里读的是真实运行值，永远准。

## 开始之前

- **怎么打开**：从「应用程序」或启动台打开 **SummitWorkbench**。装好后的位置在
  `/Applications/SummitWorkbench.app`，不在桌面上。
- **第一次打不开**：右键点图标 → 选「打开」→ 再点一次「打开」。之后就不会再拦了。
- **它长什么样**：一个独立窗口，顶上六个页签——
  **「今日」|「审批」|「第二大脑」|「项目」|「指南」|「设置」**。打开默认停在「今日」。
- **找不到窗口了**：它**不会出现在程序坞**（这是故意的，不会打扰你）。再从「应用程序」点一次
  SummitWorkbench，窗口就回来了；服务一直在跑，你的东西没丢。
- **怎么退出**：点窗口右上角的 **「退出」**（会问一次），服务就停了。下次用再打开就行。

> 每天其实就四步：**捕捉框记一笔 → 审批卡片批一轮 → 新会议拖进去 → 有疑问去问问**。

## 我想记一件事

**你要做的：**

1. 在「今日」页最上面的**简报快捷行**里，把要说的一句话打进去。
2. 按**回车**。就这样，不用点别的按钮。

右下角会冒出一句提示，比如「已记入全局 inbox · 承诺（截止 2026-09-10）」——说明记下了。

**小技巧：**

- 想让它归到某个项目，就在句子里写 `#项目名`。例如：
  `周三前给老王样章 #排版`。
- 不确定归属也没关系，直接写，它会进全局收件箱兜底。
- 写错了不用慌——它只是被记下来，还没动任何项目或飞书内容。

> **背后的细节（不看也不影响使用）**
> - 系统会自己判断这句是**承诺**（要去做的事）还是**想法**（灵光/备忘），并试着识别截止日期。
> - 就算 AI 没配好或者超时，内容也会按「想法」安全存下来，**永远不会丢**。
> - 它存到 `_vault/inbox.md`（全局收件箱），保留了待处理条目和分类标记。

## 我想处理今天的待办

「今日」页打开就是今天该干的事，从上到下依次是：

**1. 看一眼今日简报。** 顶部显示日期、健康度和「↻ 重新生成」。如果还没生成，会有一个
**「⚡ 现在生成（约 30 秒）」**按钮，点一下等半分钟就出来了。

简报分四块：

- **会议**：今天日程，已经过去的会会自动变淡。
- **待办任务**：你的主清单，按截止紧迫度排序。
- **需要行动 · 任务清单之外**：不在飞书任务里、但今天该管的（有才显示）。
- **AI 提议（非事实）** 和 **最近完成**：默认折起来了，想看再点开。

**2. 直接在简报上干活**，不用切页面：

- 任务行最右边有个 **「✓」** 小圆钮——点它，这个任务在飞书里被标记完成，那一行随即消失，
  并计入「最近完成」。
- 旁边的 **「✎」** 小圆钮——改标题或截止日期，直接写回飞书。
- 会议行尾有 **「✎」** 的，可以改会议标题和起止时间，保存后直接写回飞书日历
  （只改你自己的日程，不会邀请别人）。

**3. 有积压就去审批页。** 如果看到橙色卡片写着「N 条待确认」，点 **「去处理 →」** 直接跳过去。

> **背后的细节（不看也不影响使用）**
> - 截止徽章的颜色：今天到期是红色，剩 1–2 天是琥珀色，一周内是蓝色，更远只显示日期。
> - 行尾标着 **「近期承诺 · #N」** 的，是 AI 挑出今天最该推进的项，`#N` 就是推荐顺序。
> - 简报每天 08:00 自动生成。顶栏健康点是绿/橙/红三色——绿=正常，橙=有积压或接近预算，
>   红=有失败任务或飞书授权失效。
> - vault 里的 Markdown 原文不会因为你在这里点「✓」或「✎」而改变，Obsidian 里读到的还是
>   早上那份原始简报。
> - 待确认积压、费用超预算、定时任务失败时，系统会自动发 macOS 通知，不需要你做任何操作。

## 我想处理审批（把候选写回）

会议导入后产生的「候选」（决定、行动项）都会先堆在这里，**等你确认才会写回**。

**你要做的：**

1. 切到「审批」页。
2. 逐条看，然后选一个：
   - **「✓ 批准」**——同意，但**还不会马上写回**。
   - **「✗ 拒绝」**——不要，归档为忽略。
   - **「修改」**——要改内容、改归属项目、改落点或改截止日期，点它展开表单。
   - **「↺ 改回待确认」**——点错了可以撤回。
3. 处理完，点工具栏的 **「检查并写回」**。会先弹一个**预演**窗口，告诉你每条准备写到哪；
   你看过再点 **「应用（写回）」**，这时候才真正动数据。

**一次处理一批：**

- 每个会议分组标题右边有 **「✓ 全批」** 和 **「✗ 全拒」**，还显示这一组有几条。
- 工具栏的 **「一键拒绝过期项」**：把所有截止日期已经过去的待确认项一次性拒掉。
- 单次批量最多 100 条；超了不会发请求，缩小范围再来。

**落点怎么选（这张表建议看一眼）：**

- **飞书任务**——有截止日期、或者要落进执行清单的。
- **新建会议**——会上定了「X 时候再开一次」，就在飞书日历建一条日程。
- **项目主笔记**——你自己明确的下一步，写进项目档案的「下一步」。
- **跟进事项**——**别人**答应要做的事（写进项目档案的「跟进事项」，不进你的飞书任务）。
- **项目 inbox**——知道属于哪个项目、但还不成熟的想法。
- **全局 inbox**——实在归不清项目的，兜底，绝不丢。

> **背后的细节（不看也不影响使用）**
> - 如果一条候选显示「⚠ 暂不可批准写回」，是它缺依据或缺落点，不是出故障。点「修改」补齐
>   就能批。「✓ 全批」也只纳入**同时具备依据和落点**的条目，其余会留在待确认。
> - 「检查并写回」处理的是当前工作区**全部已决定项**，不是当前筛选或选中的那几条。
> - 拒绝项在应用之后也会进审计归档。
> - 截止日期早于今天的待确认候选，元信息里会标「已过期」。
> - 点「来源」里的会议笔记和逐字稿，会在新标签页以只读文本打开；路径始终限制在当前工作区
>   文件范围内，缺失或不支持的文件会明确报错，不会静默失败。
> - 修改候选**只动** `_vault/review/meetings.md`，不会触发任何写回。

## 我想导入一场会议

**你要做的：**

1. 在「今日」页的简报快捷行，点 **「＋ 导入会议纪要」**，会打开一个抽屉。
2. 把飞书导出的逐字稿（`.md` 或 `.txt`，带说话人和时间戳）拖进去，或者点「点击选择文件」。
3. 等它跑完。结果区会回显「处理 N / 跳过 N / 失败 N / 生成候选 N」，还有预估费用。
4. 跑完后，去**「审批」页**逐条确认要写回的内容。

整个过程是**全自动**的：归档原文 → 生成结构化会议笔记 → 把提取出的条目送进审批页。

**命名建议：** `YYYY-MM-DD-会议标题.txt`。日期和标题就是这么来的。

> **背后的细节（不看也不影响使用）**
> - 会自动处理到「生成候选进审批页」为止。**批准写回仍然要你自己在审批页确认**——系统不会
>   没经你同意就去改项目和飞书任务。
> - 关掉抽屉**不会**取消已经开始的请求；但也不承诺记住你浏览器的文件选择状态。
> - 提示「未识别为逐字稿」时：确认文件是 `.md`/`.txt` 且内容非空，别传空模板。
> - 导入和问答依赖云端模型。没配置模型时这两项暂时用不了，但**捕捉、审批、简报生成都不受
>   影响**。

## 我想看项目进展

**1. 首页的推进卡。** 「今日」页下半部分是项目推进卡，只显示**你已经在工作台的项目**。
每张卡会告诉你：git 有没有未提交的改动、项目 inbox 有没有积压、主笔记里的「下一步」是什么。
有动静的卡片左侧会高亮。

**2. 点项目名，打开「线视图」。** 一屏看到这个项目的档案区块
（当前状态 / 下一步 / 阻塞 / 跟进事项 / 决策记录）和按日期聚合的时间线
（推进日志、产物、关联会议）。

**3. 在卡上记录进展。** 每张卡有两个入口：

- **✎ 日志**——把今天的推进（跟谁聊了什么、定了什么、下一步）粘进去。可以一次勾选多个项目，
  AI 会整理成摘要归入各自时间线。**模型不可用时只存原文，绝不丢。**
- **存产物**——把和 AI 长对话产出的阶段总结、背景包、PRD 全文存进所选项目档案，自动命名 +
  生成摘要索引，之后在「第二大脑」随时能搜到。

**4. 管理项目去「项目」页。** 列出两类项目：

- **仓库项目**——`~/Documents/Work` 下的文件夹。
- **知识线程项目**——纯档案的业务线，**不需要建文件夹**，也不需要 git 仓库。

每行有状态徽标：**在工作台**（绿）/ **新**（黄，还没建档）/ **已归档**（灰）。
顶部搜索框按名字过滤，排序是 在工作台 → 新 → 已归档。

行内操作：

- **加入工作台**——把「新」文件夹建档并上首页；已归档的点它就是**恢复**。
- **归档**——从首页撤下。归档和恢复**只改项目档案的状态，文件夹和 git 历史一概不动**。
- **＋ 新建知识线程**——直接建档，可以随时改「项目 ID + 别名」。

**5. 新文件夹提示。** 工作目录里出现还没建档的文件夹时，项目区顶部会多一条横幅（不占卡片位），
逐条点 **「加入工作台」** 或 **「归档」**，处理完横幅就消失。批量管理走标题行右侧的
**「管理全部 →」**。

> **背后的细节（不看也不影响使用）**
> - 首页**不是** `~/Documents/Work` 的文件夹目录，只有已建档且在工作的项目才显示，否则项目一多
>   首页就被淹了。
> - 知识线程卡显示「知识线程」徽标、「最近活跃」日期和停滞提示（>14 天无实质更新）；仓库项目
>   卡显示 git 信号。
> - 「最近活跃」由日志和产物入库刷新。「>14 天未更新」只按**实质更新**（建档/激活/归档/改名/
>   状态确认）判断，机器活动刷不掉它。
> - 保存产物时如果勾了「同步主档案当前状态」，会先给你看将要写入的摘要预览，确认后才覆盖，
>   取消则只保存产物。
> - 以 `_vault`、`_transcripts-inbox` 这类下划线开头的系统目录**不会**出现在项目列表，也不会
>   提示「加入工作台」。

## 我想问点东西（第二大脑）

**你要做的：**

1. 切到「第二大脑」页，直接问一句，例如「网课项目最近的决策是什么？」。
2. 看回答。它分成**「事实（带来源）」**和**「建议（模型推断）」**两区，来源用 `[[笔记]]`
   链接给出。
3. 想缩小范围，先用提问框上方的**检索范围**下拉选一个项目/线程，再问。例如选「FinanceOps」
   再问「木子最近推进到哪了」。
4. 可以接着追问（「那后来呢？」），上下文会自动带上之前引用过的来源。

> **背后的细节（不看也不影响使用）**
> - 会话存在本地浏览器里，最多 10 个，可以新建/切换/重命名/删除。
> - 回答按「直接结论、事实（实际引用）、证据冲突、建议（模型推断）」分区；来源不足时会明确
>   标「无法作答」，不会瞎编。
> - 「事实」和「冲突」里的来源是**实际引用**；另外列出的「仅召回、未在回答中引用的材料」只是
>   候选上下文，**不算回答依据**。
> - 点任一来源可在只读面板核查正文、标题和日期。
> - 模型不可用时会显示错误说明，不会白屏。

## 我想同步到别的设备

你的所有内容都是本地 Markdown 文件，放在 `~/Documents/Work/_vault/`，随时可以用 Obsidian
打开查看和编辑。多设备同步靠 Git。

**你要做的：**

1. 打开「设置」页，往下找到底部的 **「高级与维护」** 折叠区，点开。
2. 在里面配置 Git 同步和多工作台。日常不用打开这一区，需要排查或切换工作区时才进来。

> **背后的细节（不看也不影响使用）**
> - 底部的「高级与维护」默认不展开，展开也不会改变数据。多工作台、Git 同步、健康检查、
>   只读预检、诊断和版本更新都在里面。
> - 系统写回会自动 git 留痕（提交信息以 `wb:` 开头），所以每一步都可追溯、可还原。
> - 生成简报时，系统会把本次产生的当日笔记、快照和相关运行信号**作为一组显式路径**提交和
>   同步，**不会**把你 vault 里其他没提交的手工改动一起带上。
> - 只有确实存在未提交的手工改动时，才需要处理 `dirty-protected` 提示。

## 我想配置模型和飞书

打开「设置」页，四张白话卡，成功状态统一是绿色「✓」：

- **工作区**——显示当前工作区文件夹。工作区就是保存会议、任务和项目资料的本地文件夹。
- **AI 模型**——粘贴 DeepSeek API Key，点「连接并验证」。成功后显示绿色「✓ 已配置」；
  没配显示灰色「未配置」；验证失败显示红色「验证失败」。自定义模型收在卡内折叠区。
- **飞书**——点「授权飞书」或「重新授权飞书」。浏览器里完成授权后，如果停在 `localhost`
  回调页，回到 SummitWorkbench 窗口继续就行。成功显示「✓ 已授权」；没连显示「未连接」；
  令牌失效显示「需重新授权」。
  > 这一步**不需要你填任何应用信息**：安装包里已经内置了飞书应用的配置，点一下就会跳到
  > 飞书的授权页。若提示「你没有使用该应用的权限」，是管理员还没把你加进应用的「可用范围」，
  > 找管理员加一下再点一次即可。
- **自动化**——开关晨间简报、每周复盘、会议同步和每天检查更新，还能调运行时间。
  点「立即运行」是人工触发，会跳过当天已运行过的调度门控；定时任务仍按星期和时间走。

## 我想撤销一次改动

**你要做的：**

1. 点窗口顶栏右上角的 **「↩ 撤销」**。
2. 在弹层里看最近的自动提交，**先看差异**。
3. 确认要还原，点一下还原。

系统每次自动写回（捕捉、日志、产物、审批应用、项目建档归档等）都会自动 git 留痕，所以能这么撤。

> **重要限制：还原只作用于 vault 文件。**
> 飞书那边已经产生的副作用（已建的任务和会议、已标记的完成状态）**撤不回来**，界面文案也会
> 明确告诉你这一点。
> 如果那个文件你有未提交的手动修改，系统会**拒绝还原**，以免覆盖你的改动。

# 常见问题

**Q：双击图标没反应 / 页面打不开？**
A：工作台是后台代理、**没有 Dock 图标**，先从「应用程序」重新打开 SummitWorkbench。
桌面 App 用的是动态端口，不要手工固定端口。还是不行就看日志
`~/Library/Logs/summitworkbench-panel.log`。

**Q：页面是旧的样子（白底表格、没有卡片）？**
A：按顺序查：
1. 点顶栏「退出」，然后**重新从「应用程序」打开 SummitWorkbench**——版本更新只在服务重启后生效；
2. 还不行，在页面按 **⌘⇧R** 强制刷新（可能是缓存了旧页面，而旧页面引用的文件已被新版本替换）；
3. 确认你打开的是 **/Applications/SummitWorkbench.app**——`/Applications` 里的
   SummitKnowledge、SummitServerAI 是**历史遗留旧产品**，内嵌旧界面，跟这套系统无关；
4. 都不行就是前端产物没重建——找维护者执行一次 `cd web && npm run build`，然后重启服务。

**Q：明明有很多项目文件夹，首页推进卡却很少/是空的？**
A：首页只显示**已建档且在工作台**的项目。没建档的文件夹先出现在「新文件夹」横幅里，点
「加入工作台」才会变成推进卡；已归档的进不了首页。「项目」页能找到并管理全部文件夹。

**Q：快速捕捉一直显示「想法」？**
A：AI 分类需要配置模型。没配置时功能照常用，只是不分类、也不识别截止日期。

**Q：拖入文件提示「未识别为逐字稿」？**
A：需要 `.md` 或 `.txt` 且内容非空。确认你导出的是逐字稿正文，而不是空模板。

**Q：导入或问答报「模型未配置」？**
A：这两项依赖云端模型，没配置时暂时用不了；捕捉、审批、简报生成等其余功能不受影响。
配置好后重启 App 即可。

**Q：模型或飞书连不上怎么办？**
A：进「设置」看对应卡片顶部的连接状态：模型重新粘贴 Key 并点「连接并验证」；飞书点
「重新授权飞书」。**授权失败时界面会直接说明原因和下一步**，最常见的两种是：
「你的账号还没有这个应用的使用权限」→ 找管理员把你的账号加进应用的「可用范围」；
「授权码无效或已过期」→ 重新点一次「授权飞书」即可。仍然失败时，在「高级与维护」里运行
在线健康检查，把白话错误提示和诊断包交给维护者。**API Key 和授权令牌不会显示在页面上，
也不会进入诊断包。**

**Q：任务在哪里点完成——工作台还是飞书？**
A：**两边都行，而且双向同步。** 在「今日」简报的任务行尾点「✓」，会直接写回飞书标记完成，
那一行随即消失并计入「最近完成」；在飞书里完成的任务，下次生成简报（或刷新后重新生成）时
也会反映过来。工作台把飞书当作任务状态的唯一真源。

**Q：为什么任务完成/编辑、或新建会议偶尔提示失败？**
A：这些写回需要飞书授权有效，并且目标还在（已删除的任务、被移动的日历事件会失败）。
**新建会议和编辑会议还需要日历写权限**：先在飞书开放平台给应用开通「日历」读写 scope，
然后在工作台重新授权一次（旧令牌不带新权限），之后就能用了。

**Q：编辑会议/任务会改到 vault 里的简报吗？**
A：不会。改动只写回飞书本体，并镜像到当日的 Web 渲染快照（该行更新或消失）；vault 里的简报
Markdown 是当天早上的原始记录，一字不动，在 Obsidian 里阅读不受影响。
