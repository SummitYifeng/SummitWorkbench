# SummitWorkbench Web 工作台 · 使用指南

> 适用版本：v0.2 · 本指南也随仓库维护：docs/product/WEB_USAGE_GUIDE.md
>
> Web 工作台是 CLI 的本地便利层：同一套数据（Obsidian vault + 审批页），打开浏览器即可完成
> 每日的「记一笔 → 批一轮 → 喂一场会」闭环。纯本地运行（127.0.0.1），不上传任何数据。

## 1. 怎么打开

```bash
wb web              # 前台启动面板，浏览器打开 http://127.0.0.1:8787
wb web --open       # 推荐：服务没在跑就后台拉起，并自动打开浏览器（通知/Spotlight 也能用）
```

也可以双击 macOS 启动器 App（`dist/SummitWorkbench.app`，需先 `scripts/build-macos-app.sh` 打包）。

> 提示：想让「打开面板」成为日常动作，把 `wb web --open` 存成一个别名或快捷指令即可。

## 2. 「今日」页（默认首页）

打开第一眼，从上到下就是今天该做的事：

### ① 快速捕捉框（最顶部）

- 输入一行，回车即记入全局 inbox，不跳转不刷新。
- AI 会自动判断这是**承诺**（要去做的事）还是**想法**（灵光/备忘），并识别截止日期；结果在右下角 toast 提示，如「已记入全局 inbox · 承诺（截止 2026-09-10）」。
- 想关联项目就写 `#项目名`（用已建档项目的名字或别名），系统会本地解析归属，如：`周三前给老王样章 #排版`。
- 模型没配置/超时也没关系：一律按「想法」兜底保存，**永远不会丢**。

### ② 待确认审批卡片

- 有积压时显示橙色卡片：「N 条待确认 · 最老已等待 X 天」+「去处理 →」按钮，一键跳到审批页。
- 处理干净后变绿色「审批已清空」。

### ③ 导入会议纪要（拖拽区）

- 把飞书导出的逐字稿（`.md` / `.txt`，带说话人+时间戳）拖进虚线区，或点「点击选择文件」。
- 点导入后**全自动**：归档原文 → 结构化笔记 → 提取项进入审批页；结果区回显「处理 N / 跳过 N / 失败 N / 生成候选 N」和预估费用。
- 文件名建议 `YYYY-MM-DD-会议标题.txt`（日期和标题的来源）。
- 自动处理只到「生成候选进审批页」；**批准写回仍要你在审批页逐条确认**——系统不会未经你同意改动项目和飞书任务。

### ④ 项目推进卡

- 每个工作项目一张卡：显示 git 未提交/领先落后、项目 inbox 积压、主笔记里的「下一步」。
- 有动静的项目卡片左侧会高亮成警告色。

### ⑤ 今日简报

- 08:00 自动生成；没生成时显示「⚡ 现在生成（约 30 秒）」按钮，点击立即生成。
- 简报正文就是当天晨间指挥台：要行动的事、最近完成、项目状态。

### ⑥ 问第二大脑

- 输入问题（如「网课项目最近的决策是什么？」）→ 回答分「事实（带来源）」与「建议（模型推断）」两区。
- 模型不可用时显示可见错误说明，不会白屏。

## 3. 「审批」页

### 单条候选操作

- **✓ 批准**：写回目标（项目主笔记 / 飞书任务 / inbox），点击即生效，无需整页刷新。
- **✗ 拒绝**：归档为忽略项。
- **↺ 改回待确认**：误操作可撤回。
- **修改**：展开表单可改正文、目标项目、落点（route）、截止日期，保存后即时生效。
- 依据或目标项目缺失的候选会显示「⚠ 暂不可批准写回」——这类是缺信息，不是故障。

### 批量应用

1. 点「预演应用」：弹窗展示零写入的 DRY-RUN 计划（每条候选要去哪）。
2. 确认无误点「确认应用（写回项目/建任务/归档）」，或直接点工具栏「应用（写回）」执行。

> 与 CLI 的关系：审批页就是 `wb review` 的图形版，读同一份 `meetings.md`；命令行和网页操作完全互通。

## 4. 状态与提醒

- 顶栏健康点：绿色=正常，橙色=有积压/接近预算，红色=有异常（失败任务或飞书授权失效）。
- 页面每 60 秒自动刷新一次；也可点右上角 ↻ 手动刷新。
- 需要主动提醒时，`wb status --notify`（launchd 定时调用）会把积压/费用/任务失败**真正发到 macOS 通知中心**。

## 5. 常见问题

**Q：页面是旧的样子（服务端渲染）？**
A：说明前端构建产物缺失。在仓库根目录执行：`cd web && npm install && npm run build`，再重启 `wb web`。

**Q：快速捕捉一直显示「想法」？**
A：分类模型不可用（未配置 `[models.capture]` 或 `[models.shared]`、Keychain 无 key、模型超时）。数据已安全保存，只是没分类；配置好模型后自然生效。

**Q：拖入文件提示「未识别为逐字稿」？**
A：需要 `.md` / `.txt` 且内容非空；请确认导出的是逐字稿正文而非空模板。

**Q：导入提示模型未配置？**
A：会议结构化需要云端模型。检查 `wb doctor --online` 或配置 `[models.meeting]` / `[models.shared]`。

**Q：问答报「问答不可用」？**
A：检查 `[models.qa]` / `[models.shared]` 配置与 Keychain 中的模型 API key（`wb doctor --online` 一键体检）。

**Q：修改审批候选后想撤销？**
A：用「↺ 改回待确认」或直接编辑回原值；审批页只改 `meetings.md`，不会触发任何写回。

## 6. 数据都去了哪里

- 快速捕捉 → `_vault/inbox.md`（带分类标记，Obsidian 里可继续编辑）。
- 会议导入 → `_vault/meetings/transcripts/`（原文）+ `_vault/meetings/notes/`（结构化笔记）+ `_vault/review/meetings.md`（待确认候选）。
- 审批应用 → 项目主笔记 / 飞书任务 / inbox + `_vault/review/archive/` 审计。
- 全部是 Markdown + 本地文件，随时可以用 Obsidian 查看，也可以继续用 CLI 操作。

## 7. 一句话总结

**每天：捕捉框记一笔 → 看审批卡片批一轮 → 把新会议的逐字稿拖进去 → 简报/问答兜底。**
